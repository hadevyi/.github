# 라벨 동기화

> 상태: 새 미리보기·생성·갱신 구현 · 실제 라벨 이전은 별도 작업

실행 정의는 [reusable-sync-labels.yml](../.github/workflows/reusable-sync-labels.yml)이다. 개인 운영 원본에서 선택한 프로필별 이름과 색상을 생성해 포함하며, 이 저장소에서 라벨 정의를 독자적으로 편집하지 않는다.

## 실행 방식

| 실행 | 동작 |
| --- | --- |
| 기존 호출·예약 실행·mode 생략 | 생성·갱신·보존 예정 목록만 표시 |
| 수동 `mode: preview` | 동일한 미리보기, 쓰기 API 호출 없음 |
| 수동 `mode: apply` | 관련 열린 Issue를 확인하고 라벨 생성·색상·설명 갱신 |
| 삭제·이름 변경 | 지원하지 않음. 별도 이전 작업에서 기록 연결 검증 후 수행 |

- 아카이브·Fork와 관리 계정 외 저장소는 실행을 거부한다.
- 명시적 적용에는 같은 저장소의 관련 열린 Issue 번호를 `issue_number`로 전달한다. PR 번호로 대체할 수 없다.
- 기존 `profile` 인수는 호환 별칭으로 유지한다. 기존 호출에 `mode`가 없으면 항상 미리보기다.
- 프로필에 없는 기존 라벨은 모두 보존한다. 기존 Issue·PR의 라벨을 재지정하지 않는다.
- 이미 같은 색상·설명인 라벨은 갱신하지 않는다. 실행 결과는 로그와 Actions 요약에서 확인한다.
- 실행 중 오류가 나면 실패로 표시한다. 적용 도중 일부 생성·갱신이 끝났을 수 있으므로 새 미리보기로 잔여 차이를 확인한다.

## 프로필 적용 대상

| 확정 프로필 | 기존 별칭 | 용도 |
| --- | --- | --- |
| `codex-governance` | 없음 | 개인 설정·규칙·스킬 관리 |
| `github-governance` | `governance` | 공통 GitHub 운영 |
| `branding-site` | `branding` | 브랜딩 사이트 |
| `branding-document` | 동일 | PDF를 함께 제공하는 브랜딩 사이트 |
| `learning` | 동일 | 학습 기록 |
| `algorithm` | 동일 | 알고리즘 풀이 |
| `github-profile` | `profile` | GitHub 프로필 |

등록되지 않은 프로필은 실패하며 기본값으로 다른 라벨을 적용하지 않는다.

## 라벨과 기록 이전

- 새 라벨은 `영문분류:한글내용` 형식이며 공백을 넣지 않는다.
- `priority`·`status`는 공통이고 `type`·영역·플랫폼·학습 분류는 프로필별로 선택한다.
- 기존 `중요도:`, `난이도:`, `영역:` 등을 이름만 보고 삭제하지 않는다.
- 기존 체계의 이름 변경·통합과 같은 분류 중복 해소는 열린·닫힌 Issue와 PR을 함께 검토하는 별도 이전 작업이다.
- 새 Form 적용은 필요한 라벨을 준비한 뒤 진행한다. Form이 라벨을 참조한다는 이유만으로 라벨이 자동 생성되지는 않는다.

## 검증 범위

- 원본의 테스트에서 미리보기 쓰기 금지·생성/갱신 범위·기존 라벨 보존·잘못된 입력·실행 이벤트·Issue 조건을 검증한다.
- 공개 저장소 9개의 기존 호출은 파일명과 별칭이 유지되어 계속 사용할 수 있다.
- 배포 후 대표 호출을 `preview`로 실행하고, 실행 전후 라벨이 동일한지 확인한다.
